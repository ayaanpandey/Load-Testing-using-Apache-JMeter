# Load Testing with Apache JMeter

Performance test suite built with **Apache JMeter** that simulates realistic user traffic against a flight-booking web app ([BlazeDemo](https://blazedemo.com), a public site built for testing practice) and measures **response time, throughput, and error rate** under increasing load.

> **Please be considerate:** BlazeDemo is a shared public demo. Keep to the `smoke` and `load` profiles, and don't run the `stress` profile against sites you don't own. To stress-test freely, point `-Jhost` at your own app.

---

## What this project demonstrates

- **Realistic user journey:** an end-to-end booking flow (Home, Find Flights, Choose Flight, Purchase) grouped under a Transaction Controller
- **Parameterization:** passenger and route data driven from a CSV Data Set Config
- **Correlation:** flight ID, price, and airline pulled from the server response with Regular Expression Extractors and passed to later requests
- **Validation:** Response Assertions confirm each page actually loaded, and a Duration Assertion flags any response slower than the SLA (default 3 s)
- **Realistic pacing:** random think time between requests, cookies cleared per iteration
- **Configurable load:** users, ramp-up, duration, host, and SLA set from the command line with `-J` properties (no editing the `.jmx`)
- **Reporting:** non-GUI execution, the JMeter HTML dashboard, and a small Python script that prints P90/P95/P99 percentiles

## User journey

```
Home Page  ->  Find Flights  ->  Choose Flight  ->  Purchase Ticket
 GET /        POST /reserve.php   POST /purchase.php   POST /confirmation.php
                  |                      ^
                  +-- extracts flight, price, airline (regex)
```

## Quick start

```bash
git clone https://github.com/<your-username>/jmeter-load-testing.git
cd jmeter-load-testing

# 1. Smoke test first (5 users, 60 s). Verifies the script works.
./scripts/run_test.sh smoke

# 2. Real load test (50 users, 5 min)
./scripts/run_test.sh load
```

On Windows, use `scripts\run_test.bat load`.

Each run creates `results/<profile>_<timestamp>/` containing:

- `report/index.html`: the JMeter HTML dashboard (open in a browser)
- `results.jtl`: raw sample data
- `summary.md`: percentile table generated by the Python script

### Test profiles

| Profile | Virtual users | Ramp-up | Duration | Purpose |
|---------|--------------:|--------:|---------:|---------|
| `smoke`  | 5   | 10 s  | 60 s  | Confirm the script and assertions work |
| `load`   | 50  | 60 s  | 300 s | Expected peak traffic |
| `stress` | 150 | 120 s | 300 s | Find the breaking point (own systems only) |

### Custom runs

Every parameter can be overridden directly:

```bash
jmeter -n -t test-plans/blazedemo_load_test.jmx \
  -Jusers=100 -Jrampup=90 -Jduration=600 \
  -Jhost=my-app.example.com -Jprotocol=https \
  -Jsla_ms=2000 -Jdata_dir=$(pwd)/data \
  -l results/custom.jtl -e -o results/custom_report
```

| Property | Default | Description |
|----------|---------|-------------|
| `users` | 50 | Concurrent virtual users |
| `rampup` | 30 | Seconds to start all users |
| `duration` | 120 | Test length in seconds |
| `host` | blazedemo.com | Target host |
| `protocol` | https | `http` or `https` |
| `sla_ms` | 3000 | Max acceptable response time (Duration Assertion) |
| `think_min_ms` / `think_range_ms` | 1000 / 2000 | Random think time = min to min+range |
| `data_dir` | ../data | Folder containing `passengers.csv` |

### Debugging the script (GUI)

Open `test-plans/blazedemo_load_test.jmx` in JMeter, **enable** the *View Results Tree* listener, set Users to 1, and run. **Never run real load tests in GUI mode.** It skews results.

## Metrics tracked

- **Response time:** average, min, max, P90 / P95 / P99
- **Throughput:** requests per second
- **Error rate:** failed assertions, HTTP errors, and timeouts
- **Active threads over time** and **response time vs. users** (from the HTML dashboard)

## How it works (key JMeter elements)

| Element | Purpose |
|---------|---------|
| Thread Group (scheduler on) | Users, ramp-up, and duration controlled by properties |
| HTTP Request Defaults | Single place for host/protocol/timeouts |
| Cookie Manager | Per-user session, cleared each iteration |
| CSV Data Set Config | Different route and passenger data per iteration |
| Transaction Controller | Measures the full booking flow as one business transaction |
| Regex Extractors | Correlate dynamic flight/price/airline values |
| Response + Duration Assertions | Functional correctness and SLA checks under load |
| Uniform Random Timer | Realistic think time |

## Extending the project

- Add a **CI pipeline** (GitHub Actions or Jenkins) that runs the `smoke` profile on each push and publishes the HTML report as an artifact
- Add a **second scenario** (e.g., browse-only users at 80% / buyers at 20%) using a Throughput Controller
- Run **distributed tests** with JMeter remote workers
- Stream metrics to **InfluxDB + Grafana** with the Backend Listener
